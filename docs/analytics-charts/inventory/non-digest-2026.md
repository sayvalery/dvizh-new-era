## Метод

Картинки не открывались (текст в них переведён в кривые — проверено: во всех SVG `<text>` = 0, только `<path>`).
Решение принималось по:

1. `alt` изображения и подпись `<figcaption>`;
2. имени файла (аватарки, `art-arrow.svg`, `thumb.webp`, `sep1..4.svg`);
3. `class` (`image-23` = аватар автора цитаты, `b-card-cover-block` + `art-arrow` = внутренняя промо-карточка, `image-24` = иконка ссылки);
4. окружающему тексту («посмотрим на данные…», «на графике…», «по данным Mediascope»);
5. геометрии SVG/размерам файла как вспомогательному признаку (легенды из цветных swatch-квадратов 17,57 px; прямоугольники разной высоты = столбики; ряды одинаковых «пилюль» с постоянным шагом по Y = табличная сетка; пропорции 1702×285 = полоса KPI-цифр, а не график).

Важный контрпример, который сбивает эвристику «описательный alt = график»: в пяти интервью серии «о девелопменте»
файлы `sep1.svg … sep4.svg` имеют осмысленный alt («Блок 2: взгляды на жизнь …»), но это **декоративные разделители блоков**,
одни и те же во всех пяти статьях. Осмысленный alt сам по себе признаком графика не является.

Тэгов `<table>` в теле статей нет ни в одной из 22 (все таблицы, если они есть, — растр/вектор внутри картинки).
