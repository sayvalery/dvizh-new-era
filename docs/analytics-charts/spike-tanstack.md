**Дата:** 2026-08-12 · **Версия под проверкой:** `@tanstack/charts@0.11.1` (pre-alpha)
**Среда:** macOS 24.1.0, Node **v22.23.1**, npm 10.9.8

**Измеренный вес:** статичный рендер — **0 КБ** клиентского JS (0 `<script>`, 0 `.js` в `dist`).
Интерактивный остров — **27–35 КБ gzip** (линия без тултипа 26,8 · линия+тултип 30,6 ·
столбцы+тултип 33,8 КБ). Поверх уже имеющегося Alpine — **+31,3 КБ gzip**, т.е. клиентский
JS-бюджет проекта вырастет примерно **втрое** (16,6 → 47,9 КБ gzip).

**Главные риски:** (1) библиотеке **15 дней**, ломающие правки уезжают в **minor**-версиях;
(2) заголовки осей жёстко зафиксированы на `font-size="11"` — чек-лист экспорта
(≥32/≥56 px) через API библиотеки **не выполняется**; (3) подписи категорий по умолчанию
**молча прореживаются**; (4) PNG требует второй зависимости с нативными бинарями.

Идти можно **только** при выполнении трёх условий: точное пиннование версии без `^`,
полная изоляция за собственной прослойкой, статичный SVG как основной режим
(интерактив — отдельным решением позже).

### 2.3. Как SVG ведёт себя в вёрстке

| Свойство вывода | Значение | Что это даёт |
|---|---|---|
| `font-family="inherit"` на каждом `<text>` | наследуется | **инлайн в статье автоматически получит Inter/Styrene A** |
| `fill="currentColor"` | наследуется | цвет текста = цвет статьи, тёмная тема бесплатно |
| `width="100%" height="100%"` + `viewBox` | адаптив | масштабируется по контейнеру |
| `role="img"` + `aria-label` + `<desc>` | есть | базовая доступность |
| CSS-переменные | только `var(--ts-chart-focus-fill, Canvas)` | с фолбэком, только для фокус-точек |
| `<script>` | **нет** | — |

Это ровно то поведение, на которое рассчитывает `design-cms.md` §3.2 вариант A
(«инлайновый SVG наследует шрифты страницы и `currentColor`») — **подтверждено фактически**.

> ⚠️ **Подтверждаю требование к порядку вызова из `design-cms.md`.** В корне SVG есть
> `style="display:block;overflow:visible"`. `sanitizeBodyHtml()` срезает **все** `style`,
> поэтому инъекция графиков обязана идти **после** санитайза — иначе разметка испортится.
> Предписанный в `design-cms.md` порядок верен и обязателен, а не «на всякий случай».

**Вывод по п. 2: ✅ ДА, полностью. Это самый сильный результат спайка.**

## 3. Alpine-адаптер

**Чем проверял:** `@tanstack/charts/alpine` в jsdom с **alpinejs@3.15.8** — точной версией
из `apps/web/package.json` (специально понизил песочницу с 3.16.1 до 3.15.8).

### Совместимость

Peer-требование — `alpinejs: ">=3.15"`. В проекте `^3.15.8`. **Совпадает, но с нулевым
запасом:** 3.15 — это floor. Проект проходит только потому, что уже на 3.15.8.

Монтирование выглядит так:

```ts
import Alpine from 'alpinejs'
import { charts } from '@tanstack/charts/alpine'
Alpine.plugin(charts)
Alpine.start()
```
```html
<div x-data="{ chartOptions }" x-chart="chartOptions"></div>
```

Результат прогона (`t6-alpine.mjs`):

```
resolved Alpine shape: plugin=function start=function
Alpine version: 3.15.8
Alpine.start() OK
host element classes: my-chart ts-chart-host
svg rendered by x-chart: true
viewBox: 0 0 720 360 | aria-label: Заявки по месяцам
<text> count: 11
<path> count: 1
first tick text: Январь
```

**Работает с Alpine 3.15.8.** По пути пришлось починить три вещи, и все три — артефакты
jsdom, а не библиотеки, фиксирую честно, чтобы не выглядело как «завелось с первого раза»:
`Alpine.plugin is not a function` (в Node резолвится CJS-сборка Alpine — нужен
`alpinejs/dist/module.esm.js`), `ShadowRoot is not defined`, и
`Failed to execute 'dispatchEvent' … parameter 1 is not of type 'Event'` (Node 22 имеет
свои `Event`/`CustomEvent`, их надо перекрыть jsdom-овскими). В браузере ничего этого нет.

### Что адаптер требует на клиенте

- Alpine ≥ 3.15 (уже есть) + `Alpine.plugin(charts)` до `Alpine.start()`.
- Полный DOM: `ResizeObserver`, `MutationObserver`, `getComputedStyle`.
- **Только браузер.** Документация прямо: «It does not prerender a server shell or provide
  a hydration path», в таблице SSR у Alpine стоит `Server output: None`.
- Элемент с директивой становится `.ts-chart-host` и **владеет своим содержимым**.

### ❌ Директива не гидратирует, а дублирует

Проверил, что будет, если положить SSG-SVG внутрь элемента с `x-chart` (`t7-alpine-hydrate.mjs`):

```
svg count now: 2
SSR node still in document? true
```

**Получаются два графика.** Директива не адоптирует существующую разметку — она добавляет
свою рядом. Это не баг, а документированное поведение, но конкретный способ выстрелить
себе в ногу: «сделаем SSG-график и на него же навесим `x-chart`» не работает.

**Вывод по п. 3:** адаптер совместим и работает, но он — инструмент для *client-only*
графиков. Для нашей SSG-модели он **не тот инструмент**; правильный путь — `mountChart`
из `@tanstack/charts/dom` (см. п. 6). Alpine при этом остаётся полезен как **триггер**
острова (`x-init`/`x-intersect`), а не как рендерер.

## 4. Экспорт

**Чем проверял:** импорт и вызов `@tanstack/charts/export` в голом Node; затем сборка
полного экспортного конвейера в Node с растеризацией.

### 4.1. Что умеет штатный `./export`

Документация (`docs/guides/exporting.md`) обещает три пути: `renderChartSvg` (строка SVG),
`serializeChartSvg` (сериализация смонтированного SVG с инлайном вычисленных CSS-свойств),
`renderChartImage`/`downloadChartImage` (растр PNG/JPEG/WebP).

Прогон в Node (`t3-export.mjs`):

```
--- import @tanstack/charts/export in bare Node
OK imported. exports: [ 'downloadChartImage','downloadChartSvg',
                        'renderChartImage','serializeChartSvg' ]

--- call serializeChartSvg with no DOM
FAIL: TypeError : target.querySelector is not a function

--- call renderChartImage with no DOM
FAIL: TypeError : target.querySelector is not a function
```

**Важный отрицательный результат: подпуть `./export` browser-only ЦЕЛИКОМ — не только
растр, но и SVG-сериализация.** Все четыре функции принимают смонтированный DOM-элемент.
В документации это сказано только про растр («Raster export is browser-only»); про
`serializeChartSvg` приходится догадываться. Импортируется модуль без ошибок (нет обращения
к DOM на верхнем уровне) — падает только вызов, что делает ошибку отложенной.

**Практический вывод:** штатный экспорт рассчитан на кнопку «Скачать» в браузере у
интерактивного графика. Для **пакетной генерации файлов на сборке** он бесполезен.
Хорошая новость: он и не нужен — `renderChartSvg` из ядра покрывает SVG, а его вклад
в бандл 1,6 КБ gzip, т.е. кнопку «Скачать» можно будет добавить почти бесплатно.

### 4.3. Standalone-файл требует нашего пост-процессинга

Достоинство инлайна (`font-family="inherit"`, `currentColor`) в отдельном файле становится
недостатком: наследовать не от кого — шрифт схлопнется в дефолтный serif, цвет в чёрный.
Это ровно тот риск, который `design-cms.md` §3.2 (вариант D) отметил как «отдельный файл
не наследует шрифты страницы» — **подтверждаю, и вот точная цена вопроса.**

Проверил `theme` (`t8-theme.mjs`) — явная тема снимает бóльшую часть проблемы:

```
background rect emitted: true
currentColor still present: false      ← все цвета стали конкретными
palette used for stroke: true
CSS vars remaining: [ 'var(--ts-chart-focus-fill, Canvas)' ]
```

Но `font-family` в API **нет вообще**: `grep -rn "fontFamily|font-family"` по
`chart-spec.md` и `rendering-and-export.md` — пусто. `ChartTextTypography.fontFamily`
существует, но управляет только *измерением* текста для расчёта полей, а не атрибутом в
выводе. В SVG всегда уезжает `font-family="inherit"`.

Итого пост-процессор из 4 строк (проверен, работает):

```js
svg = svg
  .replace('width="100%" height="100%"', `width="${W}" height="${H}"`)   // фиксируем размер
  .replace('<svg ', '<svg xmlns="http://www.w3.org/2000/svg" ')          // standalone-файл
  .replace('style="display:block;overflow:visible"', `style="font-family:${FONT}"`)
  .replace(/var\(--ts-chart-focus-fill, Canvas\)/g, BG)                  // убрать CSS-переменную
```

Это не хак по чужой разметке — только корневой элемент и одна переменная с фолбэком.
Приемлемо, но обязано жить в одном месте нашей прослойки.

### 4.4. ❌ Заголовки осей зафиксированы на 11px — чек-лист не выполняется

Самая неприятная находка. В экспортном файле остаётся `font-size="11"`:

```
  size=42  key=x-tick-label:string:6:Январь       "Январь"
  size=42  key=y-tick-label:number:2500           "2500"
  size=11  key=x-label                            "Месяц"    ← заголовок оси
  size=11  key=y-label                            "Заявки"   ← заголовок оси
```

Причина в типах (`node_modules/@tanstack/charts/dist/types.d.ts:206`):

```ts
export interface ChartAxisLabelOptions {
    text: string
    offset?: number | 'auto'
    motion?: ChartMotionDefinition
}
```

**Ни `fontSize`, ни `fontWeight`.** У tick-подписей они есть, у заголовка оси — нет.
11px на холсте 1280px — это нечитаемо, а чек-лист требует ≥ 56px для `social`.

**Обходной путь (рекомендуемый, и он лучше по сути):** не использовать заголовки осей
библиотеки в экспортных пресетах вообще. Заголовок, подзаголовок и сноску наша прослойка
и так обязана рисовать сама (`design-channels.md` требует заголовок ≥32/≥56 и сноску) —
значит композиция «заголовок + график + сноска» принадлежит нам, а библиотеке остаётся
только область данных с tick-подписями. Правку `font-size` по `data-ts-key="x-label"`
регексом делать **не надо**: это ровно то «manual DOM mutation to paper over a missing
capability», которое запрещает authoring-гайд самой библиотеки.

### 4.5. ⚠️ Подписи категорий молча прореживаются

При крупном кегле библиотека сама выбрасывает подписи, которые не влезают (`t10-thin.mjs`):

```
fontSize:42 (по умолчанию)   x-подписей: 3/4 ["Январь","Март","Апрель"]   ← «Февраль» пропал
fontSize:42, thin:false      x-подписей: 4/4 ["Январь","Февраль","Март","Апрель"]
fontSize:42, rotate:-30      x-подписей: 3/4 ["Январь","Март","Апрель"]   ← поворот не помог
fontSize:30                  x-подписей: 4/4 ["Январь","Февраль","Март","Апрель"]
```

Для аналитики застройщиков «молча потерялся февраль» — дефект данных, а не косметика.
Лечится `axis.tickLabels.thin: false`, и это **обязательный дефолт нашей прослойки** с
валидацией на пересечение. Отдельно отмечу: `rotate: -30` прореживание не отменяет —
похоже, оно считается до учёта поворота (мелкий изъян библиотеки).

**Вывод по п. 4: 🟡 ЧАСТИЧНО.** SVG в Node — да. Штатный `./export` для сборки не годится
(browser-only целиком). PNG в Node — да, но своим растеризатором. Произвольный размер — да.
Два ограничения (кегль заголовка оси, прореживание) обходятся композицией и настройкой,
но обход обязан быть зашит в прослойку, иначе чек-лист экспорта будет нарушаться тихо.

## 5. Вес

**Чем проверял:** `esbuild --bundle --minify --format=esm --platform=browser`, затем
`gzip -9` и `zlib.brotliCompressSync`.

|---|---:|---:|---:|
| **Статичный SSG-рендер (ничего не уезжает)** | **0** | **0** | **0** |
| Линия, интерактив без тултипа | 77 919 | **26,8 КБ** | 24,1 КБ |
| Линия + тултип | 88 905 | **30,6 КБ** | 27,4 КБ |
| Столбцы + тултип | 97 661 | **33,8 КБ** | 30,1 КБ |
| Линия + столбцы + тултип | 99 691 | 34,5 КБ | 30,6 КБ |
| Alpine 3.15.8 **один** (базовая линия проекта) | 47 352 | 16,6 КБ | 15,0 КБ |

| `./export` отдельно | 3 791 | 1,6 КБ | 1,4 КБ |

**Ключевые числа:**

- **Базовый рендер = 0 КБ клиентского JS.** Не оценка — факт из `dist` билда Astro:
  ноль `.js`-файлов, ноль `<script>`. Требование выполняется идеально.
- **Вклад charts поверх Alpine = 31,3 КБ gzip** (47,9 − 16,6). То есть один интерактивный
  график **утраивает** клиентский JS проекта: 16,6 → 47,9 КБ gzip.
- Столбцы дороже линии на 3,2 КБ gzip (band-шкала + прямоугольная геометрия).
- Тултип стоит 3,8 КБ gzip — берём осознанно, а не по умолчанию.
- Zero d3 в бандле (см. п. 1) — заявленная гранулярность подпутей реальна.

**Укладываемся ли.** Для статики — да, с абсолютным запасом. Для интерактива — формально
«не укладываемся» в дух ограничения CLAUDE.md («только Alpine ~15KB, так и должно
оставаться»): 31,3 КБ — это удвоение бюджета на одну фичу. Но нюанс в том, что цена
платится **только на страницах с графиком** и **только если мы вообще делаем интерактив**.
Поскольку п. 2 показал, что статика полностью закрывает потребность статей, а
`design-channels.md` §4 прямо относит интерактивность к «можно не делать в первой версии», —
**рекомендую в v1 интерактив не подключать вообще и остаться на 0 КБ.** Тогда вопрос веса
снимается, а не решается компромиссом.

## 6. Гидратация / SSR

**Чем проверял:** отрендерил SVG в Node, положил в контейнер в jsdom, сверху вызвал
`mountChart`, и сравнил **идентичность DOM-узлов** до и после (`t4-hydrate.mjs`).

```
SSR svg present: true | path d prefix: M76.6,337L276.41,159.6L476.23,225.1L676.
--- after mount ---
svg count in container: 1
SAME NODE as SSR svg?   true      ← тот же самый DOM-узел
data-ssr-marker kept?   null
path d identical?       true      ← геометрия не пересчиталась
same path NODE?         true      ← тот же самый <path>
host has interaction?   true | getScene: true
```

**Гидратация реальна и честная:** `mountChart` адоптирует существующий корень, сопоставляет
детей по `data-ts-key`, сохраняет узлы и не перерисовывает геометрию. Ни мигания, ни
пересоздания SVG. Механизм — `reconcileChartSvg`: «adopts a compatible existing root,
matches children by `data-ts-key`, moves retained nodes into their new order».

Две оговорки, найденные фактически:

1. **Свои атрибуты на корне SVG не выживают** — `data-ssr-marker` затёрся (`null`).
   Реконсиляция владеет атрибутами корня. Значит, помечать SSG-график своим атрибутом
   на `<svg>` нельзя — метку вешать на внешний контейнер.
2. **Alpine-директива гидратацию НЕ поддерживает** — даёт два SVG (п. 3). Гидратация есть
   только у `mountChart`/`mountChartRenderer` и у фреймворковых адаптеров
   (React/Preact/Vue/Solid/Svelte/Octane). У Alpine в таблице SSR — `Server output: None`.

**Условия детерминизма** (из `docs/guides/ssr-and-hydration.md`, все выполнимы у нас):
явные размеры на сервере; определение из тех же данных; никакого `window`/`Date.now()`/
`Math.random()` при построении; стабильные `idPrefix` и ключи; одинаковые форматтеры.
Отдельно: автоматические поля зависят от метрик текста, на сервере используется
детерминированное приближение, браузер после загрузки шрифтов **перемеряет и делает
релейаут** — то есть небольшой сдвиг подписей после подключения Inter ожидаем и является
задуманным поведением.

**Вывод по п. 6: ✅ ДА** — отдать статичный SVG со сборки и «оживить» его без перерисовки
можно, но исключительно через `mountChart`, а не через Alpine-директиву.

## 8. Дизайн нашей прослойки

Решение владельца: **маркетологи и статьи никогда не видят API библиотеки — только наши
пресеты.** Ниже спроектированный слой; он согласован с `design-cms.md` (шорткод-вариант A
на сайте + файловый эндпоинт-вариант D для каналов) и `design-channels.md` (три пресета
канвы). Код ниже — скетч для отчёта, в проект не добавлялся.

### 8.1. Место в структуре

```
apps/web/src/lib/charts/
├── types.ts        ← ПУБЛИЧНЫЙ контракт: ChartSpec, ChartPreset, ChartSize. Нет TanStack.
├── presets.ts      ← реестр пресетов: ChartSpec → определение графика.  ЕДИНСТВЕННОЕ
│                     место во всём проекте, знающее про @tanstack/charts
├── render.ts       ← renderChartSvg-обёртка: renderForWeb() / renderForExport()
├── raster.ts       ← PNG через resvg (только для скриптов сборки, не для страниц)
└── validate.ts     ← проверки чек-листа: кегль, число подписей, вес, прореживание

apps/web/src/components/ui/DataChart.astro        ← вставка в страницу/статью (0 КБ JS)
apps/web/src/lib/inject-charts.ts                 ← шорткод <figure data-chart> → SVG
apps/web/src/pages/charts/[period]/[slug].svg.ts  ← файловый эндпоинт (вариант D)
scripts/export-charts.mjs                         ← CLI: PNG для писем и соцсетей
```

Соответствует конвенциям проекта: данные и CMS-функции — в `lib/`, переиспользуемый
компонент — в `components/ui/`, пакетная задача — в `scripts/`.

### 8.2. Публичный интерфейс (то, что видит остальной код)

Ключевая мысль: на входе — **данные + выбор пресета + подписи**, и больше ничего.
Ни марок, ни шкал, ни каналов, ни единого типа из TanStack.

```ts
// types.ts — ЗДЕСЬ НЕТ ИМПОРТОВ ИЗ @tanstack/charts
export type ChartPreset =
  | 'trend-line'      // динамика показателя по периодам
  | 'category-bars'   // сравнение категорий
  | 'share-split'     // доли внутри целого
  | 'compare-periods' // два периода рядом

export type ChartChannel = 'web' | 'email' | 'social'

export interface ChartSpec {
  preset: ChartPreset
  rows: ReadonlyArray<Record<string, string | number | null>>
  x: string                     // имя поля категории/периода
  y: string | readonly string[] // имя поля значения (или несколько серий)
  title: string                 // обязателен: идёт в aria-label и в заголовок файла
  summary?: string              // вывод с цифрой — в <desc>, в alt и в подпись
  labels?: { x?: string; y?: string }
  unit?: '%' | '₽' | 'шт' | ''
  footnote?: string
}

export interface ChartArtifact {
  svg: string
  width: number
  height: number
  alt: string                   // собран из title + summary, ≤150 символов
  warnings: readonly string[]   // нарушения чек-листа
}
```

### 8.3. Три выхода из одного описания

```ts
// render.ts
export function renderForWeb(spec: ChartSpec): ChartArtifact
// адаптивный SVG, font-family:inherit + currentColor, tabIndex:-1, тема НЕ задаётся
// (наследует страницу и тёмный режим). Вызывается в frontmatter → 0 КБ клиентского JS.

export function renderForExport(spec: ChartSpec, channel: 'email' | 'social'): ChartArtifact
// фиксированный холст (1200×H / 1280×H), явная theme (непрозрачный фон, конкретные цвета),
// кегли из таблицы канала, thin:false, xmlns, font-family впечатан в корень.

// raster.ts (только Node, только скрипты)
export async function renderPng(spec: ChartSpec, channel: 'email' | 'social'): Promise<Buffer>
```

Пресеты и кегли живут в одной таблице — источник правды для обоих каналов:

```ts
// presets.ts
const CHANNELS = {
  web:    { tickFont: 14, titleFont: 20, stroke: 2,   bg: null      /* наследует */ },
  email:  { width: 1200, tickFont: 26, titleFont: 34, stroke: 3, bg: '#FFFFFF' },
  social: { width: 1280, tickFont: 42, titleFont: 56, stroke: 4, bg: '#FBF9F6' },
} as const
```

Заголовок/сноска **не отдаются библиотеке** (её `ChartAxisLabelOptions` не умеет кегль,
см. 4.4) — они рисуются нашей композицией: для web обычным HTML в `DataChart.astro`
(бонус: живой текст для SEO и скринридера, чего и требует `design-channels.md`), для
экспорта — нашим внешним `<svg>`-враппером вокруг области данных.

### 8.4. Использование — API библиотеки не видно нигде

```astro
---
// DataChart.astro
import { renderForWeb } from '@/lib/charts/render'
const { spec } = Astro.props
const chart = renderForWeb(spec)
---
<figure class="my-8">
  <figcaption class="text-subhead text-gray-500 mb-3">{spec.title}</figcaption>
  <div set:html={chart.svg} role="group" aria-label={chart.alt} />

```

Маркетолог в CMS видит только: показатель, период, пресет, заголовок, вывод.
В теле статьи — `<figure data-chart="approval-by-region"></figure>` (вариант A из
`design-cms.md`). Слова `lineY`, `scaleBand`, `defineChart` не встречаются нигде за
пределами `presets.ts`.

### 8.5. Точки соприкосновения с TanStack — их ровно четыре

| # | Что | Где | Строк |
|---|---|---|---|
| 1 | `defineChart` + марки `lineY`/`barY` + compact-шкалы | `presets.ts` | ~40 на пресет |
| 2 | `createChartScene(def, size, { typography })` | `render.ts` | 1 |
| 3 | `renderChartSvg(scene, { ariaLabel, ariaDescription, idPrefix, tabIndex })` | `render.ts` | 1 |
| 4 | *(опционально, только если появится интерактив)* `mountChart` | остров | 1 |

**Всё. Два файла, четыре вызова.** `@resvg/resvg-js` в `raster.ts` — пятая точка, но она
уже не про TanStack и при смене движка не меняется.

**Цена замены движка:** переписать `presets.ts` + `render.ts` (построение определения и
вызов рендера) — по опыту прогонов этого спайка это несколько часов. Всё остальное —
`ChartSpec`, компонент, шорткод-инъекция, эндпоинт, CLI-экспорт, схема CMS, тексты
статей — **не меняется вообще**, потому что не знает, чем рисуется SVG. Именно это делает
ставку на 15-дневную библиотеку допустимой.

**Что обязано быть в прослойке с первого дня** (иначе чек-лист нарушается молча):
`thin: false` на подписях категорий; валидатор минимального кегля и числа подписей
(`warnings` в `ChartArtifact` + FAIL в `scripts/audit.sh`); `tabIndex: -1` для статичных
графиков (дефолт `0` делает нефокусируемую картинку фокусируемой без причины);
стабильный `idPrefix` из slug показателя и периода — иначе два графика на одной странице
столкнутся градиентами и clip-путями.

| Цена интерактива, если понадобится | 85,5 КБ gzip | ECharts 170 КБ, Vega 263 КБ — в 2–3 раза дороже |
| Риск | 🟡 последний релиз 2025-02 — темп замедлился | зато **нет** риска ломающих minor: API не двигается |

**Почему не ECharts:** технически безупречен по SSR (нативный `renderToSVGString`, без
шима) и максимально зрелый, но (а) 170 КБ gzip за интерактив — в 5,5 раза дороже
TanStack, (б) это конфигурационная модель (`option`-объект), а не грамматика, поэтому
переезд с TanStack потребует переосмысления пресетов, а не переписывания вызовов,
(в) canvas-ориентированная архитектура, SVG — второй режим.

**Почему не Vega-Lite:** JSON-спека соблазнительна (пресет = шаблон спеки, маркетолог
теоретически может править), и зрелость максимальная (с 2015). Но 263 КБ gzip за
интерактив и заметно более тяжёлый рантайм делают его худшим выбором, если хоть однажды
понадобится оживить график. Как чистый build-time-рендерер — вполне жизнеспособен, держу
третьим номером.

**Почему не «свой d3»:** самый лёгкий (14,3 КБ) и максимально устойчивый — d3-модули не
меняются годами. Но всё, что TanStack даёт бесплатно (автоподбор полей по метрикам текста,
прореживание подписей, доступность, tick-логика, реконсиляция), придётся написать и
поддерживать самим. Это дороже, чем один раз переписать `presets.ts` при смене движка.
Резервный вариант «если вообще все библиотеки не подошли».

**Триггеры активации плана Б:** (1) ломающий minor, который не удалось починить за день;
(2) 3+ месяца без релизов при незакрытых блокерах; (3) появление требования, которое
упирается в жёсткие ограничения вроде 4.4 и не обходится композицией.

## Итоговый вердикт

> ## 🟡 ИДЁМ С ОГОВОРКАМИ

**Что решает вопрос в пользу «идём»:**

1. **Главное требование выполнено полностью и с запасом.** Реальный билд Astro 5.17.3
   даёт `dist` из одного `index.html` с настоящими `<text>`, кириллицей и **нулём** JS.
   Это ровно та механика, на которую рассчитан вариант A из `design-cms.md`, и она
   проверена не рассуждением, а сборкой.
2. **Инлайновый SVG ведёт себя как часть сайта**: `font-family="inherit"` +
   `currentColor` — шрифты проекта и тёмная тема достаются бесплатно, без единой строки.
3. **Чек-лист экспорта из `design-channels.md` §3 выполним**: произвольный холст, кегли
   подписей, непрозрачный фон, детерминированность, PNG 27,5 КБ при лимите 60 КБ.
4. **Самый лёгкий из грамматических движков** — 30,6 КБ gzip против 85 у Plot и 170 у
   ECharts, если интерактив когда-нибудь понадобится.
5. **Гидратация настоящая** — те же DOM-узлы, без перерисовки.
6. **Прослойка получается тонкой** — 4 вызова в 2 файлах, замена движка стоит часы.

**Оговорки, которые обязаны быть выполнены — иначе «не идём»:**

1. **Пин точной версии `0.11.1` без `^`.** Не пожелание: 0.8.0 и 0.9.0 сломали публичный
   API и приехали **minor**-версиями. `^` = сайт может перестать собираться после
   случайного `pnpm install`.
2. **Ни одного импорта `@tanstack/charts` вне `apps/web/src/lib/charts/**`**, с машинной
   проверкой в `scripts/audit.sh` (категория «запрещённые импорты» там уже есть).
3. **Статичный SVG — основной и единственный режим v1.** Интерактив не подключать:
   он утраивает клиентский JS (16,6 → 47,9 КБ gzip), а `design-channels.md` §4 сам
   относит его к «можно не делать».
4. **Заголовки/сноски рисует наша композиция, а не библиотека** — её заголовки осей
   зафиксированы на 11px и требование ≥32/≥56 px через API недостижимо (4.4).
5. **`thin: false` + валидатор кегля и числа подписей** в прослойке с первого дня —
   иначе подписи категорий будут молча исчезать из графиков (4.5).
6. **План Б заранее назван и оценён** — Observable Plot, миграция = переписать
   `presets.ts` + `render.ts`.

**Что придётся согласовать с владельцем (CLAUDE.md запрещает новые зависимости
без разрешения):**

| Зависимость | Роль | Где нужна | Замечание |
|---|---|---|---|
| `@tanstack/charts@0.11.1` | движок рендера | build-time (+клиент, если будет интерактив) | pre-alpha, 15 дней, пин без `^` |
| `@resvg/resvg-js@2.6.2` | PNG для писем/соцсетей | **только** build-time / CLI | нативный napi-модуль, **12 платформенных бинарей** — проверить сборку под linux-x64 в Docker и darwin-arm64 на MacBook |

Если PNG в первой версии не нужен (только SVG на сайте) — вторая зависимость не нужна
вовсе, и тогда согласовать надо ровно один пакет, который к тому же не попадает в
клиентский бандл.
